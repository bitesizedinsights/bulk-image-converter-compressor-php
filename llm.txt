# Bulk Image Converter Compressor PHP

> PHP client for bulk image conversion, compression and resizing (WebP, AVIF, JPEG, PNG, HEIC input) via Apify, returns typed DTOs.

Key facts:
- Package: `bitesizedinsights/bulk-image-converter-compressor`
- Install: `composer require bitesizedinsights/bulk-image-converter-compressor`
- PHP: ^8.3, Guzzle ^7 || ^8
- Namespace: `ImageConverter`
- Entry class: `ImageConverter\Client`
- Auth: Apify API token, set via `Client::setApifyKey()`, falls back to env `APIFY_API_TOKEN` or `APIFY_TOKEN`

## Docs
- [README](https://github.com/bitesizedinsights/bulk-image-converter-compressor-php/blob/master/README.md): usage

## API
- `Client::__construct(?Config $config = null, ?GuzzleHttp\ClientInterface $http = null, ?Closure $sleeper = null)`
- `Client::setApifyKey(string $apiKey): static` - sets the Apify API key; without it `APIFY_API_TOKEN` or `APIFY_TOKEN` is read from the environment, and `MissingApiKeyException` is thrown on the first API call if neither is set
- `Client::convert(array $urls = [], OutputFormat $outputFormat = OutputFormat::WebP, int $quality = 80, ?int $maxWidth = null, ?int $maxHeight = null, ?bool $keepAspectRatio = null, ?bool $stripMetadata = null, ?string $backgroundColor = null, array $uploadKeys = [], ?string $uploadStoreName = null, ?int $runTimeout = null): ConvertedImage[]` - one run for all images (1-1000 in total from urls and uploadKeys), waits for it, returns one ConvertedImage per processed image (fewer rows on the free plan (first 3), with duplicates, at the spending limit or after a shutdown; index is 1-based in the deduplicated list, URLs first then upload keys; a time_limit error row counts as processed); null options are not sent
- `Client::start(...same arguments as convert()): DTO\Run` - starts one run (1-1000 images) and returns at once; the run-start POST is retried only as described under retry safety, so after any other error a run may exist (check before starting again; `ApiException::$runId` is set when the response named the run)
- `Client::getRun(string $runId): Run` - one lookup, any status, never throws because of the status; unknown ID: ApiException code 404
- `Client::wait(Run|string $run, ?int $timeout = null): Run` - polls until SUCCEEDED (timeout default Config::$timeout, 0 = check once, negative = InvalidArgumentException), keeps polling on ABORTING/TIMING-OUT, throws ApiException (runId, statusMessage) on FAILED/ABORTED/TIMED-OUT or timeout; never aborts the run
- `Client::results(Run|string $run): ConvertedImage[]` - dataset of a SUCCEEDED run without waiting, ApiException otherwise (also for failed/aborted/timed-out runs); a Run object with actId is not refetched, so pass the one from wait() or the ID; `convert()` rows and `Results` helpers apply
- `Client::abort(Run|string $run): Run` - aborts a run (POST /actor-runs/{id}/abort) and returns its new state; does not check which Actor the run belongs to
- Run ID rules: IDs must match [A-Za-z0-9]{1,64}, else InvalidArgumentException before any request; getRun()/wait()/results() throw ApiException when the run belongs to another Actor than Config::$actorId (may need one GET /acts/{actorId} per client)
- `Config(string $actorId = 'bite-sized-insights/bulk-image-converter-compressor-and-resizer', string $baseUrl = 'https://api.apify.com/v2', int $timeout = 600, int $requestTimeout = 90, int $maxRetries = 3, float $retryBaseDelay = 1.0, float $retryMaxDelay = 30.0, ?int $runTimeout = null)` - run timeout: sent as `timeout` (seconds) query of the run-start POST only; order: convert(..., runTimeout: ?int) > Config::$runTimeout > Config::$timeout (so a run cannot outlive the client wait); 0 = send nothing (Actor limit 600 s), negative = InvalidArgumentException; retries 429 (Retry-After as seconds or HTTP date), 5xx and connection failures with backoff; POST run start only on 429 or failed connection
- Retry safety and time limit: the run-start POST is repeated only after a 429 or a connection failure that shows the request was never sent (cURL errors 5, 6, 7, 35, Guzzle 8 `ConnectTimeoutException`, or a non-timeout connection failure without a cURL code; on Guzzle 7 never after cURL error 28); `Retry-After` is honoured on 429 and 503 (above `retryMaxDelay` the error is thrown); 408 and other 4xx are never retried. In `convert()`, `Config::$timeout` covers the run start, the wait for the run and all retries (start(), getRun(), wait() with its own $timeout, results() with at least 30 s and abort() each get it separately, and only convert() ever aborts a run): a retry whose wait would pass it is skipped, each request timeout is cut to the time left plus 5 s, reading the results of a successful run keeps at least 30 s, and if polling fails because the time is used up the run is aborted best effort and the last request's error is thrown
- Helpers and DTOs:
  - `Results` (final class, static methods only): inputCount(array $urls, array $uploadKeys = []): int (deduplicated, normalized count), missingIndexes(array $results, int $inputCount): list<int> (1-based indexes without a row), isComplete(array $results, int $inputCount): bool, unprocessed(array $results, array $urls = [], array $uploadKeys = []): array{urls, uploadKeys} (inputs without a row, original keys preserved; feed to a second convert() call)
  - `Run` (final readonly, JsonSerializable): id: string, status: RunStatus, defaultDatasetId: ?string, startedAt: ?string, finishedAt: ?string, statusMessage: ?string, actId: ?string; isFinished(), isSuccessful(), toArray() (Apify field names), fromArray(array) (needs id and a known status, other non-string fields become null)
  - `ConvertedImage` (final readonly, `fromArray(array)`): index: int, source: string, sourceType: SourceType, status: ConversionStatus, outputUrl: ?string, outputKey: ?string, sourceFormat: ?string, outputFormat: ?string, sourceBytes: ?int, outputBytes: ?int, bytesSaved: ?int, savedPercent: ?float, sourceWidth: ?int, sourceHeight: ?int, outputWidth: ?int, outputHeight: ?int, error: ?string; serialization: implements JsonSerializable and toArray() in the Actor's camelCase shape, fromArray(toArray()) restores it; helpers isSuccessful(), isFailed(), isLarger(), wasResized()
- Enums:
  - `OutputFormat`: WebP ('webp'), Jpeg ('jpeg'), Png ('png'), Avif ('avif'), Original ('original'), Gif ('gif'), Tiff ('tiff'), Bmp ('bmp')
  - `ConversionStatus`: Success, Failed
  - `SourceType`: Url, Upload
  - `RunStatus`: Ready, Running, Succeeded, Failed, Aborting, Aborted, TimingOut ('TIMING-OUT'), TimedOut ('TIMED-OUT'); isFinished(), isFailure()
- Exceptions:
  - `InvalidArgumentException`: no images, more than 1000, url >2048 chars, uploadKey >256 chars, uploadStoreName >63 chars, quality outside 1-100, maxWidth/maxHeight outside 0-16000, invalid backgroundColor, negative runTimeout (also thrown by the Config constructor), malformed run ID, negative wait() timeout
  - `ImageConverter\Exception\ApiException`: failed request, malformed response, failed/aborted/timed-out run, run not finished within Config::$timeout (the run is aborted best-effort, message ends 'and was aborted' if that worked, property runId holds the run ID; for a failed run the message is 'Actor run ended with status X: <statusMessage>' when the run has a non-empty string statusMessage (control chars stripped, max 500 chars), property statusMessage holds the raw reason capped at 2000, null when absent), unmappable dataset item
  - `ImageConverter\Exception\MissingApiKeyException` (extends ApiException): no API key set and no `APIFY_API_TOKEN`/`APIFY_TOKEN` in the environment
  - `ImageConverter\Exception\RateLimitException` (extends ApiException): HTTP 429, property retryAfter (seconds)
  - `ImageConverter\Exception\SpendingLimitException` (extends ApiException, final): HTTP 402 (monthly usage or spending limit reached), code 402, property errorType (Apify error type, null if unreadable), never retried; catch it before ApiException
- Single bad images do not throw; they are returned with status Failed and an error message.

## Limits
- Free Apify plan: 5 runs in total, each converting the first 3 images (URLs plus upload keys); Console test runs have the same cap

## Example
```php
use ImageConverter\Client;
use ImageConverter\OutputFormat;

$client = (new Client())->setApifyKey(getenv('APIFY_API_TOKEN'));
$images = $client->convert(['https://example.com/photo.png'], outputFormat: OutputFormat::WebP, quality: 80, maxWidth: 1600);

foreach ($images as $image) {
    echo $image->isSuccessful() ? $image->outputUrl : $image->error, "\n";
}
```
